## 3. Bugs diagnosed (from code, then ticketed)

- **App-launch (ticket-019):** `IntentExecutor` calls `getLaunchIntentForPackage`, but the
  manifest has **no `<queries>`** → on Android 11+ that returns `null` for every app
  (package visibility) → silent failure (audit-log only).
- **Proximity-wave (ticket-020):** `ProximityWaveDetector` uses a fixed ~5.5 cm "near"
  threshold; many sensors report "far" as `maximumRange` (often 5.0 cm) → permanently
  "near" → never completes the far→near→far cycle. Fix = classify relative to `maximumRange`.

### ADRs
- **ADR-0003 — Core/app separation:** four Gradle modules — `:engine` (OPEN, pure-JVM, the carve target), `:engine-android` (CLOSED bindings incl. T5 Keystore sealing), `:app` hosting a CLOSED `catalog` package behind an SPI. Apache-2.0; internal split now, public subtree-carve deferred to a monetization milestone; a CI guard compile-enforces `:engine` staying Android-free. Reached via a 2-architect, 2-round debate (the moat is the curated catalog + macros + UX + brand, not the engine).
- **ADR-0004 — Tiered third-party app control:** there is **no universal cross-app automation API**. Preference order: Tier 1 app-specific deep link/SDK (exact actions, e.g. Spotify App Remote `playUri`) → Tier 2 vendor-neutral intents (`MEDIA_PLAY_FROM_SEARCH`, deep links) → Tier 3 MediaSession transport (global `dispatchMediaKeyEvent`; targeted via Notification Listener) → Tier 4 accessibility injection (fragile, disclosed, deterministic-only, last resort). App-list mapping via `queryIntentActivities(MAIN/LAUNCHER)` + `loadLabel/loadIcon` and scoped `<queries>` — **no `QUERY_ALL_PACKAGES`**. Compliance: no `isAccessibilityTool`, prominent disclosure + consent, deterministic only (no agentic), per-app ToS = user's responsibility, sideload/F-Droid hedge.
